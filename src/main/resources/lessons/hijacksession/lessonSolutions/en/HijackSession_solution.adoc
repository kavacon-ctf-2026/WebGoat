== Session prediction is prevented

The old exercise used sequential values and timestamps in `hijack_cookie`. Those values made it
possible to predict another user's session identifier. The fixed lesson generates 256 random bits
for each identifier and encodes them as an opaque Base64URL value.

The server records the owning signed-in WebGoat username and expiration time. It authenticates a
cookie only when the identifier is active and belongs to the current username. Invalid, expired,
or other-account identifiers receive a new session for the current user; they never authenticate
as the target account. The cookie is `Secure` and `HttpOnly` and expires after 30 minutes.

There is no valid prediction payload for this fixed version. A request that receives a new cookie
has created or renewed your own lesson session; it has not accessed another user's session.
