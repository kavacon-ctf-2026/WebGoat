== Try it out...

The verifier ignores the `jku` URL supplied by a token and reads keys only from the deployment's
trusted HTTPS JWKS URL (`JWT_JKU_TRUSTED_JWKS_URL`). That setting is empty by default, so verification
fails closed until an operator configures an issuer key set. Submit a token signed by that issuer;
tokens backed by a client-provided JWKS are rejected.
