== Safe account summary

The original exercise used an injectable lookup to read data from another table. Reading password or cookie fields through a user-controlled query would expose credentials, so this lesson now demonstrates a safe boundary instead.

Choose one of the listed account names. The application validates the selection and binds it to a fixed query against user_data. It returns only the number of matching rows; it does not read user_system_data or return any password or cookie.

In the second form, confirm that the safe summary does not retrieve passwords. The confirmation is checked against a fixed allowlist and does not query credential data.
